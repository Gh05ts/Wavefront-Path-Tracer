# HDR environment lighting

Scene manifests can load an equirectangular Radiance RGBE `.hdr` panorama for
backgrounds, reflections/refraction and illumination:

```json
"environment": {
  "file": "../gltf-research-scenes/scenes/common/sunflowers_environment.hdr",
  "intensity": 1.0,
  "rotation_degrees": 0.0
}
```

Place this object at the top level of the scene manifest. The file path is
relative to that manifest; intensity and rotation default to 1 and 0. Intensities
must be finite and nonnegative; rotations must be finite. Invalid or missing
maps fail explicitly. Removing the object restores the preset's existing sky
gradient or black background. Intensity zero keeps a black environment rather
than falling back to the procedural sky.

Rotation is right-handed yaw around world +Y: a feature facing +X moves toward
-Z at +90 degrees. The unrotated panorama's top is +Y, its center column faces
+X, and its three-quarter column faces +Z, matching the orientation documented
by the downloaded research scenes. Panoramas use linear RGB radiance; no sRGB
conversion, exposure, normalization or clipping to [0,1] is applied on loading.
Intensity multiplies both lighting and visible environment radiance. Display
exposure/tone mapping is separate. OpenEXR environment input is not implemented.

## Sampling and renderer integration

The loader decodes floating-point RGB with stb_image and uploads a float4 CUDA
texture. Longitude wraps; latitude clamps; radiance lookup uses bilinear filtering.
The sampling distribution uses a cell average of the bilinear luminance footprint
(`1/8, 3/4, 1/8` in each texture axis), weighted by each cell's exact spherical
solid angle. This gives bright neighboring cells useful sampling probability;
an additional 1% uniform-sphere component preserves global support. Radiance
texels themselves are unchanged. A black map uses a uniform-sphere distribution.
An alias table selects a texel, then longitude and cos(latitude) are sampled
within it. The resulting PDF is measured per steradian and evaluated consistently
for directions generated by either sampling strategy. Sampling handles polar
rows and longitude seams without dividing by sin(theta) at a pole.

Diffuse, imported specular/glossiness and nonzero-roughness metal surfaces sample the environment with
shadow rays. Their next-event and BSDF escape contributions use the power
heuristic to avoid double counting. Primary camera rays and the existing
delta metal/glass paths evaluate the map directly when they escape. Area
lights and punctual lights keep their existing separate sampling paths. Standard
and persistent wavefront execution use the same environment helpers.

With an active HDR map, diffuse continuations mix 50% cosine directions and 50%
environment directions. Finite GGX retains its BSDF continuation distribution.
Unlike a shadow connection, each continuation traces
the real geometry and can cross glass before reaching the sun. Throughput uses
the complete mixture density; direct-light MIS uses the same competing density.
Samples below the geometric surface terminate instead of being resampled with
an incomplete PDF. This is fixed sampling, without adaptive pixel allocation,
transparent shadow rays or material roughening. It helps
nearly parallel glass connections; arbitrary specular chains remain difficult.

HDR environments replace the procedural sky; they do not replace explicitly
declared mesh, point, spot or directional lights. Scene top lights are also
additional illumination. Disable an artificial top light when the imported
scene should use only its declared lights and environment. The existing
`capture_lighting` intervention is rejected when an HDR environment is configured,
so its sky/area-light experiment cannot silently acquire an extra source.

The photon-mapped caustic emitter does not emit photons from HDR environments.
Glass entry/exit orientation and rough-metal GGX sampling were corrected in
integrator version 4; see the [BMW firefly diagnosis](diagnostics/bmw-hdr-fireflies/README.md).
Disabling photon mapping does not suppress camera-traced caustic paths through
glass or reflected from metal. Unsupported glTF material extensions remain
unsupported. This feature is not a complete reproduction of Blender
or PBRT materials, atmosphere, or volumetric scattering.

## Indirect firefly suppression

Integrator 11 adds a configurable indirect contribution clamp, default **10**,
following Cycles' practical indirect sample-clamp approach. Concentrated HDR
sunlight can produce legitimate but very rare glass/metal caustic paths even
with correct BSDFs and direct-light MIS. Sampling the unobstructed world map
does not solve a refracted connection through curved glass.

`--clamp-indirect 10` limits each indirect contribution's mean absolute linear
RGB value after throughput and MIS, before accumulation and SPP averaging.
All components receive one scale, preserving their ratios. First-surface
direct illumination, primary backgrounds and first-bounce emitter/environment
hits remain unclamped. Glass boundaries count as scattering events. Both
wavefront modes, light types and terminal glass/coat connections share the
same accumulation helper. Neither HDR radiance nor path throughput is clipped.

For capture JSON use `"indirect_radiance_clamp": 10`. Set the value to **0**
(`--clamp-indirect 0` on the CLI) for raw unclamped transport. Nonzero clamping
is deliberately biased: it reduces rare specks by removing some bright indirect
energy, and can dim real caustics/reflections. It does not remove ordinary
low-sample Monte Carlo noise or replace denoising. Existing captures are not
modified; newly generated references record the chosen setting. Use explicit
zero when reference qualification requires unclamped transport.

The default matches Blender's current indirect-clamp property, but the renderer
does not reproduce all of Cycles' filtering, caustic solvers or denoising:
[Cycles defaults](https://github.com/blender/blender/blob/main/intern/cycles/blender/addon/properties.py),
[contribution clamping](https://github.com/blender/blender/blob/main/intern/cycles/kernel/film/light_passes.h),
[Blender clamping documentation](https://docs.blender.org/manual/en/5.2/render/cycles/render_settings/light_paths.html).

## Captures, checkpoints and distributed workers

Map bytes, intensity and rotation enter scene/render fingerprints. Render
integrator version is now **11**, so older render checkpoints cannot silently
resume with the new implementation. Captured frame metadata records the
integrator version and environment settings/dimensions. Denoiser checkpoint
formats are unchanged; reference budgets must be requalified for new captures.

The indirect clamp also enters the render fingerprint and capture metadata.
Distributed protocol version is now **7**; coordinator and workers must use the
same build. With asset transfer enabled, the map is included even if it lives
outside the geometry directory, and is checksum-verified in the worker's reserved
`__environment/map.hdr` cache path. Environment-only procedural scenes also work.
Without asset transfer, workers need access to the configured map path.

## Example and validation

`assets/scenes/breakfast_room_hdr.json` configures the downloaded Breakfast Room
extended glTF and its own HDR map, at intensity 1 and rotation 0. The preset's
extra top light is disabled. The existing imported directional light remains.
`Path-Tracer-Denoiser/configs/breakfast_room_hdr_preview.json` uses its exported
camera and captures 320×180 at 4 input + 128 reference SPP, with caustics disabled.

Run from the renderer directory, using a fresh output directory:

```bash
/tmp/ntasad-capture-build/dataset_capture \
  ../Path-Tracer-Denoiser/configs/breakfast_room_hdr_preview.json \
  ../Path-Tracer-Denoiser/runs/breakfast-hdr-new
```

CPU tests cover HDR decoding above 1, invalid data, distribution normalization,
black-map fallback, orientation/rotation, importance sampling near poles,
sample/PDF agreement, a known irradiance integral, manifest validation, fingerprint
changes and environment-only asset catalogs. GPU tests check analytic constant-map
diffuse illumination using combined MIS contributions, environment shadows,
linear HDR lookup, intensity, rotation, resource reset and the procedural-sky
fallback. A loopback transfer test exercises external environment maps alongside
geometry and environment-only scenes, including worker cache reuse.

Additional GPU regressions integrate a compact 50,000-radiance source both
directly and through a parallel glass slab against independent numerical
quadrature, including the bilinear texture footprint and finite-depth Fresnel
transmission. A tilted diffuse normal checks geometric hemisphere clipping
against its known projected-area integral. See the BMW diagnostic for the
finite-sample limits of whole-image noise ratios and spot-count comparisons.

A two-frame HDR-lit camera sequence also checks standard/persistent agreement
and the frame/sequence guide contract. Comparisons allow normal FP32 rounding;
bit-identical radiance is not required. Real preview references are for appearance
inspection only and are not convergence-qualified training labels.

The final RTX 3090 preview is in the denoiser's ignored
`runs/breakfast-room-hdr-preview-v2/` directory (`comparison.png`,
`reference-preview.png`, HDR frame and display/provenance metadata). Its buffers
are finite. The final two-frame mode comparison in `runs/hdr-support-check-v2/`
has a maximum absolute radiance difference of about 1.91e-6 and identical guides.
Eight focused renderer test executables passed, plus config and worker checks.
These checks and startup-inclusive capture timings are not a performance benchmark.
