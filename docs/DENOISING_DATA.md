# Denoising dataset capture

The optional `dataset_capture` executable feeds the separate `../denoiser`
research project. It uses `RenderTaskRenderer` for tiled linear radiance sums,
normalizes by the actual sample count, and exports float32 EXR input/reference
pairs with JSON metadata. The main renderer's PPM output, task protocol, and
checkpoint formats remain unchanged.

For v5 NTASAD companion layers and verified v4 reference reuse, see the
[v5 workflow](../../denoiser/dataset_generation/V5.md). It uses a separate
layer-only export; the uniform paired-frame contract below remains unchanged.

```bash
cmake -S . -B build -DPATHTRACER_BUILD_DATASET_CAPTURE=ON
cmake --build build --target dataset_capture frame_export_tests --parallel 2
build/dataset_capture ../denoiser/configs/demo_capture.json ../denoiser/data/demo-smoke
```

OpenEXR development libraries and pkg-config are required only when enabling
this option. The executable takes a capture configuration and a new output
directory. Run from the renderer root or build directory for preset resolution.

Configuration fields include `sequence_id`, `scene` (or `scene_file`, relative
to the configuration), `width`, `height`, `tile_width`, `tile_height`, `samples`,
`reference_samples`, `sample_start`, `max_depth`,
`russian_roulette_start_depth`, `persistent_wavefront`, `caustics`,
`caustic_photons`, `caustic_radius`, and a nonempty `frames` array. Each camera
object may specify `position`, `target`, `up`, and `vertical_fov_degrees`.
Omitted camera fields use the scene's default camera position/direction and
world-up; camera objects are independent, not incremental keyframes.

First-hit guides are generated by `generateFrameGuides` in the renderer's
existing traversal compilation unit. A separate, unjittered guide pass captures
linear albedo, shading/geometric normals, forward depth, backward camera motion,
and surface/history validity. Its temporary output is tile-local. It does not
alter path queues, RNG consumption, or accumulation.

The first implementation supports camera motion through static scenes and
uniform sampling. Every frame uses separate PCG32 input/reference sample ranges.
References share the input integrator and fixed photon-map settings. The smoke
configuration's small reference count checks the pipeline, not convergence.
Photon-map construction currently repeats per frame. Distributed dataset export,
adaptive sampling, animation, and capture checkpoint/resume are subsequent work.

The canonical [frame contract](../../denoiser/docs/frame-format.md) and
[Python validation instructions](../../denoiser/README.md) live with the denoiser.
New capture metadata includes `scene_fingerprint` for grouping independent of
display names, cameras, and sample budgets. The existing render/checkpoint
fingerprint computation is unchanged. See the denoiser's
[reference convergence and split workflow](../../denoiser/docs/reference-convergence-and-splits.md).

`frame_export_tests` runs without a GPU and checks HDR/UINT round trips,
projection conventions, invalid-pixel rejection, and overwrite protection.
Passing a new directory argument preserves a cross-language fixture:

```bash
build/tests/frame_export_tests /tmp/frame-fixture
```

## Controlled lighting captures

For the demo preset, `dataset_capture` accepts an optional `capture_lighting`
object. The sky-only intervention is `{"sky": true, "area": false}`. A square,
downward-facing area emitter can be added with:

```json
"capture_lighting": {
  "sky": false,
  "area": true,
  "center": [-1, 6, 0],
  "size": 4,
  "emission": [24, 24, 24]
}
```

`size` is the side length in world units; `emission` is linear RGB emitted
radiance. `sky: true` together with `area: true` enables both sources. The
emitter is actual geometry and casts shadows; moving/resizing it can change
visibility. The lighting experiment checks that primary albedo, normals, depth
and validity remain identical across conditions, with emitters outside the
cameras. Equal emitted power can be maintained by scaling radiance inversely
with area; this does not imply equal image exposure or sampling variance.

Overrides are restricted to the demo preset and use its unchanged base
geometry/materials. Metadata records canonical `capture_lighting`, a
`geometry_fingerprint` for the base scene, and scene/render capture identities
that include the intervention. Render task keys still use the driver's normal
prepared key. Captures without this option retain their original behavior.
The main renderer CLI, distributed configuration, and checkpoint identities
are unaffected; the override is an experiment in the capture tool.

The denoiser's `lighting-study` command performs independent reference
qualification, equal-budget control/diverse training, checkpoint freezing,
and evaluation by lighting condition. Its camera partitions share geometry;
they are labelled as a within-scene ablation, not a strict scene-disjoint test.

## Planned 1080p dataset and frame resume

The sibling denoiser repository's
[`dataset_generation`](../../Path-Tracer-Denoiser/dataset_generation/README.md)
contains scene-specific cameras, six trajectory types, independent scene splits,
frame-resumable launch scripts, a `nohup` SSH launcher, and separate 1024/4096-SPP
reference workflows. Capture remains local and uses uniform positive SPP.

`dataset_capture` accepts an optional half-open frame range:

```bash
build/dataset_capture CONFIG.json OUTPUT --start-frame 2 --end-frame 8
```

The configuration still contains the complete original camera list. Rendering a
subrange preserves frame numbers, preceding-camera motion guides and per-frame
sample IDs. Only selected frame outputs must be absent; existing selected frames
are rejected. The Python launcher validates/skips completed frames and invokes
only missing ranges. The renderer itself does not trust/skip existing output,
and does not checkpoint samples within an unfinished frame.

An optional integer `sample_stride` in capture JSON reserves a fixed sample-ID
interval per frame. It must be at least `samples + reference_samples`; its
default is exactly that sum, preserving older captures. A stride of 8192 permits
switching between 4+1024 and 4+4096 SPP without changing any noisy sample IDs.
Input/reference ranges stay disjoint, and references at the lower budget are a
prefix of the larger reference range. Metadata records the stride. This is not
an independent reference replicate for convergence measurement.
